## 1.1 中央钱箱不重复生成

- **改法**：把家里的占用判定抽成带半径的 `ChoukaBoxBusyRange(wp, radius)`
  （`02_private_box.lua`），原来的 `ChoukaBoxBusy(wp)` 变成它的封装（家里仍用 35）。
  中央刷箱前先 `ChoukaBoxBusyRange(wp, CHOUKA_CENTER_BOX_RANGE)`，不是 0 就跳过。
- **为什么中央用小半径（25）**：`center1~6` 是半径 ≈70 世界单位的正六边形，相邻两点只差 ≈60；
  用 35 会让相邻点的箱子互相"看见"，导致明明空着也不刷。

## 1.2 十连

**改法**：
1. 两个技能都发（照 DSA `lua/GAME/PureDraw/01_crate_event.lua:55-56`）：
   `SpecialPower_LuckyUnitCrate` + `SpecialPower_LuckyUnitCrateX10`。**钱由日冕技能自己扣**，脚本不重复扣。
2. 结算改成"原生结果有几个就补几个"：`spawnCount = getn(batch.ids)`，上限 `CHOUKA_MAX_DRAW_BATCH = 10`。
   单抽天然 1、十连天然 10 —— **同一条链路，只是 N 不同**。
3. 收批窗口改成"每来一个结果就重新数满 `CHOUKA_BATCH_FRAMES` 帧"，十连跨帧也不会劈成两批；
   再加 `CHOUKA_BATCH_MAX_FRAMES = 30` 兜底。
4. 一次补多个时按小圆环散开（`CHOUKA_SPAWN_SPREAD = 18`），避免 10 个叠成一个点。

**为什么「发技能」节点改成非一次性**：技能改成"房主确认开局后才发"（否则公告期间就能白嫖抽卡），
而节点从进游戏 1 秒就开始求值，`DeactivateUponSuccess` 会提前自我停用 → 改成 `false`，
脚本内用 `CHOUKA_DRAW_POWER_GRANTED` 保证只发一次。

## 1.3 房主配置改成两个二选一（去掉开局资金）

| 按钮 | 文字 | 写入 |

| 1 | `箱子包括全部阵营` + 选中时加 `√`（**默认**，作者 2026-10 指定） | `CHOUKA_DRAW_SCOPE = 0` |

- 按钮编号不写死：确认 = 选项数+1、重看公告 = 选项数+2。

# 二、第二轮（4 项，作者 2026-10 实测）

## ① 中央油井：真名就是 `centerOil1` / `centerOil2`

**现象**：上一版改完，中央油井依旧占不下来。

**根因（两个都成立）**：
1. `docs/02` 那张对象表**过时了**。它写"中央两座油井都叫 `Center2`、重名"，
   于是上一版把按真名取对象改成了"按几何位置找 `OilDerrick`"。作者实测确认：
   **地图里就是 `centerOil1` / `centerOil2`**。已把 `docs/02` 那一行改正并标注作废。
2. 更致命的一条：上一版把"占点"写在了"刷中央钱箱"**前面**。占点里只要有一句调用不存在/报错，
   整个节点当帧就中断 → **中央钱箱也跟着不刷了**（这就是第二轮第③条）。

**改法（`06_center.lua` 整份重写）**：
- **刷钱箱永远排在最前面**，占点逻辑放后面，任何报错都伤不到刷箱。
- 油井定位：**先按真名** `GetObjectByScriptName("centerOil"..k)`，拿不到才退回
  "离航点 `center` 250 以内的 `OilDerrick`"（几何兜底保留，防以后改名）。
- 所有可选 API 都套 `type(x) == "function"`，`ChoukaBuildGroundTypeList` 没定义就跳过本次。
- **加诊断播报**（`CHOUKA_CENTER_DEBUG = 1` 时）：
  - 定位结果（只播一次）：`中央油井定位：1号=有 2号=有 1号坐标=(2859,3026)`
  - 每回合刷箱：`中央钱箱：第3回合刷了6个/6个点位`
  - 领先者变化 / 每 150 秒：
    `中央油井1 领先=3 进度=2 归属=0 计数=0-0-4-0-0-0`
    （`计数` 是 P1~P6 各自在半径 200 内的单位数 —— 一眼看出"到底有没有数到人"）
- 占点规则照《双兵种作战-狭路相逢》`Troop Selection/Oil Capture.lua`：
  每 5 秒扫半径 200，"领先方**连续领先 3 次**（≈15 秒）才算占领"，所有者驻守/无人时进度回落，
  换人挑战从 1 重数；占领时 `NAMED_TRANSFER_OWNERSHIP_PLAYER` 真的转所有权 + 公播。
- 数单位改成"卡池单位全集"过滤器（`ChoukaBuildGroundTypeList()`，箱子/建筑都不在其中），
  再用 `ObjectPlayerScriptName` 按玩家归类 —— 不再用 `Include = "CAN_ATTACK"` 这种没在本图验证过的写法。

> 如果这次还占不下来，看三行播报就能定位：
> ①`1号=无` → 名字/类型不对；②`计数=0-0-0-0-0-0` → 过滤器没数到人；
> ③`领先=3` 但 `进度` 一直回到 0 → 中途有人打断（正常，说明机制在跑）。

## ② 保底单位：狗 → **工程师**（并修好"被自己抽卡系统吃掉"）

**现象**：没单位时，起重机旁边会冒出 1 个**随机 T1 单位**，而不是保底单位。

**根因**：旧版用 `CREATE_OBJECT` 无名生成**警犬 `AlliedScoutInfantry`**，出生事件照样触发
`onUnitCreateEvent`；而 `AlliedScoutInfantry` 在卡池登记表里 → 被当成"原生抽卡结果"收进批次 →
3 帧后删掉 → 补 1 个随机卡池单位（Lv.1 所以是 T1）。**玩家看到的是"军犬变成了随机 T1 单位"。**

**改法（两层保险，按作者的实测情报）**：
1. **兜底单位换成工程师**：苏联阵营给 `SovietEngineer`，其余一律 `AlliedEngineer`
   （`05_dog.lua` 的 `ChoukaFallbackUnitType`）。作者实测：**原生抽卡不会出盟军/苏联工程师**，
   所以这两种类型在 `gen_allunits.lua` 生成时**已剔除**，不登记出生事件 → 脚本自己生成的兜底单位
   **天生不可能被拦截**。`神州工程师`（`CelestialEngineer`）**会**出现在原生结果里，所以继续登记；
   `帝国（升阳）工程师`没用也不要，既不登记也不拿去兜底。
2. **仍然登记 id**：生成前把 `GetNextObjectId()` 写进 `ChoukaScriptCreated`，
   万一以后有人把工程师登记回钩子，也不会被误删（照 `12_puredraw_replace.lua` 的 `ChoukaSpawnUnit`）。
3. **位置**：从起重机往出生点走 55%（`CHOUKA_DOG_FORWARD`），出生点太近就用起重机旁 60 单位，
   避免压在起重机 footprint 上导致生成失败。
4. **节流**：每个玩家各自 5 秒一次（`CHOUKA_DOG_RETRY_SECONDS`），不再每秒重试刷屏。
5. **计数口径改了**：只要玩家**还有任何卡池单位**（含工程师本身）就不补，
   否则一个只有工程师的玩家会每 5 秒再收到一个。
6. 投放时给该玩家一条左下角提示"你场上没有单位，已在你家投放 1 个工程师（去碰箱子抽卡）"。

> ⚠ 节点名仍叫「保底军犬」（`05_dog.lua`）：**故意不改名**。JSON 地编若是合并导入，
> 改节点名会留下一个旧节点的副本，而旧节点的代码正是"投放警犬被吃掉"的那版，等于把 bug 又装回去。
> 名字与实物不符这件事，以本文件的说明为准。

## ③ 中央 `center1~6` 钱箱又不刷了

**根因**：就是 ①-2 —— 刷箱代码被排在会报错的占点代码后面，节点当帧中断。
另一个次要原因：上一版给刷箱加了 `CHOUKA_ROUND >= 1` 的门槛，于是**开局后要等 120 秒**才第一次刷，
和以前"开局就有"的观感差异很大。

**改法**：刷箱挪到最前面；去掉 `>= 1` 门槛 —— **开局立刻刷一次，之后每回合（`CHOUKA_ROUND` 变化）刷一次**，
点位有箱子就跳过，和家里的 `box11` 完全一样。每回合还会播报"刷了几个/6 个点位"。

## ④ 海里仍会抽到陆地单位（帝国武士），偶尔能抽到潜艇

**现象**：水里开箱，多数还是陆地单位（如帝国武士），偶尔出一次小潜艇。

**根因（三条）**：
1. **原生结果是空军时，z 不能用**：我们拿"原生结果单位的位置 z"当"这一格的地表高度"，
   但空军结果的 z 是**飞行高度**（离地几百），于是判成陆地 → 抽陆地单位。
   → 这就是"偶尔才对"的原因（取决于引擎这一抽给的是什么类别）。
2. **水里生成时 z 没抬到水面**：原生结果单位可能站在**海床**上（z 比水面低），
   把船生成在水下会失败 → 触发"换另一类再试"的兜底 → 于是出了一个陆地单位。
   "偶尔出潜艇"就是那几次 z 恰好等于水面。
3. 判定阈值写死 40，没有参考物。

**改法**：
1. 原生批次是空军时（`batch.nativeAir == 1`），**z 这一路不参与判定**（传 `nil` 进去）。
2. **水里生成把 z 抬到水面**：`onWater == 1` 且 `z < CHOUKA_WATER_SURFACE_Z（0）` 时改用 0。
3. 阈值改成**自校准**：`ChoukaWaterZThreshold()` = `min(陆地参考高度 / 2, 40)`，
   陆地参考取航点 `box11` 的 z（岛上箱子点），拿不到就用 `crane1` 的位置。
4. 判定仍然**只投"是水"的正票**（引擎类别 / 贴图名 / 地形高度 / 修正后的 z，任一路说是水就算水）。
5. 生成失败会播报一句（罕见，不刷屏）：
   `抽卡生成失败：JapanAntiNavyShipTech3（水陆=1 z=0 地形=-18 阈值=40）→ 换另一类再试`
   —— 下次再出现"海里出陆地单位"，看这行就知道是判定错还是生成失败。
   （开关 `CHOUKA_DRAW_DEBUG`，定位完改 0。）

## ④ 真正的元凶：Lua 源文件带 UTF-8 BOM（一次废掉 10 个节点）

加了日志通道之后，下一局的日志直接给出答案：

```
[抽卡hex] 节点就绪：解锁科技
[抽卡hex] 节点就绪：收入
[抽卡hex] 心跳 tick=1 started=nil round=nil boxLeft=nil lv=nil hud=no 节点就绪=收入,解锁科技
[抽卡hex] 节点就绪：HUD
[抽卡hex] 节点就绪：发技能
```

16 个节点里只有（当时是 15 个，第四轮后加了「单位登记」） **收入 / 解锁科技 / 发技能 / HUD**（+自检）跑起来了；开局、随机箱清理、初始化、私有箱、
抽卡初始化、保底军犬、中央油井、按钮栏、AI对手、帧循环 **全都没跑** → `started=nil`
（开局流程压根没启动，所以公告、房主配置一起消失）。

对照源文件 1:1 吻合：**这 10 个节点里都含有一个带 UTF-8 BOM 的 lua 文件**，活着的 4 个节点一个 BOM 都没有。

**机理**：之前批量改 `exAddTextToPublicBoard(...)` 用了 PowerShell 的 `Set-Content -Encoding utf8`，
PS 5.1 会**自动写 BOM（EF BB BF）**。BOM 拼进 payload 后落在 `#!ra3luabridge` 之后，
**Lua 4.0 把 `EF BB BF` 当非法 token → 整条 payload 解析失败 → 该节点静默不执行**
（游戏里不弹 `last token read: '<eof>'`、不报错、什么都不发生）。

**修复**：
- `node .dsh-tools/scratch/strip_bom.js` 批量去掉 BOM；
- `tools/sync-scriptsdata.js` 读到 BOM **直接报错拦下**，绝不生成坏包；
- 规矩：**改 Lua 只用 Node 脚本或编辑器存「UTF-8 无 BOM」，别用 PowerShell `Set-Content`**；
- 开局节点（`03_start.lua`）在关键路径上，播报改成 `_LOG`（只写日志），
  这样即使"消息区/公屏"这两个可见通道将来出错，也拖不死开局流程。

## ① HUD 为什么全无（已定位，确定是 bug）

旧版 `20_hud.lua` 用的是 **`exCreateCustomText` / `exCustomTextUpdateText`** ——
这两个函数**日冕这个 mod 根本没有**（`教程.lua` 的 API 表和官方模板里都只有
`exCreateCustomTextForPlayer` / `exCustomTextUpdateTextForPlayer` / `exCustomTextUpdateVisibilityForPlayer`）。
一调用就报错，而 `ChoukaHudReady` 又是在**建文字之前**就置 1，于是：
报错 → 标记已就绪 → 之后每秒都跳过 → **整个 HUD 永远不再重试，一行字都没有。**

**改法**：
- 逐玩家文字换成真 API：`exCreateCustomTextForPlayer(playerName, {Index, Content, X, Y, Color, Size, AlignX, AlignY})`
  + `exCustomTextUpdateTextForPlayer` + `exCustomTextUpdateVisibilityForPlayer`
  （照 `日冕地图lua例子\目标血条UI显示模板.lua:119/151/159` 与 DSA 海克斯选卡界面）。
- `ChoukaHudReady` 改成**建完之后**才置 1；每个玩家单独记录，失败的下秒重试。
- 每个 `ex*` 调用都套 `type(...) == "function"`，缺 API 只丢一行日志，不中断节点。
- **关键信息同时写进右上角计分板**（`exScoreBoardSetText` 是教程里就有的老 API，最稳）：
  第 7~10 行显示 回合 / 倒计时 / 抽卡等级 / 各档概率。
  这样就算左下角逐玩家文字的位置不对，玩家也一定能在右上角看到数据。

## ② 为什么整局一条 `_ALERT` 都没有（已定位，确定是 bug）

所有播报以前都只走 `exAddTextToPublicBoard`（玩家说的"公屏"）。这个 API 本身存在
（mod 自带示例 `Example_origin_01_print/init.lua` 就用它），但**实测在这局里什么都没显示**，
于是"流程走到哪了"完全没法判断。

**改法 —— 诊断通道铺开（新增 `lua/chouka/00_alert.lua`，构建时拼到每一个节点的最前面）**：

| 通道 | API | 看得到吗 |
|---|---|---|
| 日志文件 | `exPrintln("[抽卡hex] …")` | 游戏里看不到，**事后能翻**：`E:\CoronaLauncher\CoronaData\Logs\EnhancerCorona-<时间>.dll.log` |
| 左下角消息区 | `exMessageAppendToMessageArea(…)` | 能看到（DSA 全图用了 220 处） |
| 公屏 | `exAddTextToPublicBoard(msg, 10)` | 保留，能不能看见看 mod 版本 |

`_LOG(msg)` 只写日志（节点自检用，不刷屏）；`_ALERT(msg)` 三路全打。
另外：以前 02/03/07/09/13/16 里是**直接**调 `exAddTextToPublicBoard`，现在全部改成 `_ALERT`。

> ⚠ 坑：批量替换时把 `_ALERT` 自己的定义也替换成了递归调用（`function _ALERT(msg) _ALERT(msg) end`）。
> 已经删掉旧定义，`_ALERT` 只在 `00_alert.lua` 里定义一次。

## ③ 这次怎么定位"断在哪"—— 新增「自检」节点 + 节点就绪标记

- 新增 **`抽卡hex/自检`** 节点（`00_selfcheck.lua`，排在**第一个**）：每 10 秒往日志写一行

  ```
  [抽卡hex] 心跳 tick=30 started=1 round=0 boxLeft=90 lv=1 hud=yes 节点就绪=开局,随机箱清理,…
  ```

  一眼看出：脚本活着没、开局门控过没过、回合/倒计时有没有在动、哪些节点跑起来了。
- 每个节点主文件顶部加了一条 **`ChoukaMarkNodeReady("节点名")`**（只记一次，只进日志）：
  测试后翻日志就能看到"节点就绪：xxx"到底列出了哪些节点 —— **没列出来的那个就是断掉的节点**。
- 顺带修掉一个隐藏冲突：`ChoukaCountPlayerUnits` 在 `05_dog.lua` 和 `20_hud.lua` 里**各定义了一次**
  （参数含义还不一样），后定义的会覆盖前一个。现在拆成 `ChoukaDogCountUnits` / `ChoukaHudCountUnits`。

# 四、第四轮（实测：MCV 没删 / 一箱多单位算多次 / 海陆仍判错 / HUD 跑到左上角）

# 六、第六轮（水陆判定：改用"从地图里提取的死数据掩码"）

## 6.1 为什么放弃"运行时猜"

试过的方案按顺序：单看地形高度 → 四路信号正票（原生海军/贴图名/高度/落点 z）→ 加"开箱者脚下"启发式
→ 箱子坐标 + 全图采样校准水位。全都不稳，根因是**运行时能问到的东西都不代表"这个点在不在水里"**：

| 试过的判据 | 为什么不成立 |
|---|---|
| `exTerrainGetHeightByPos` 高度 | 水底与陆地是**连通的同一套高度体系**（作者在地编里往水底放标记，Z 直接显示 0），海床和浅滩、低地混在一起，没有可靠阈值 |
| 抽出来的单位的 z | 箱子浮在水面，单位的 z 反映水面/飞行高度，不反映地形 |
| 引擎原生结果的类别 | 引擎的箱子不按地形选单位：实测在 h=100 的陆地点照样吐出 `CelestialWaveriderIFV_Water` |
| 箱子自身坐标 | 箱子浮在水面，同理代表水面高度而不是地形 |

**结论：地图是死的，就用死数据。** 直接把地图的海陆抄成一张表，运行时只查表。

## 6.2 数据从哪来（可复现）

- 地图文件夹里自带的预览图 `[cor]每人一小块地抽卡hex.tga`（**实为 PNG**，610×610）：
  **蓝色 `rgb(68,94,106)` = 海**，其余像素（灰 `rgb(145,146,151)`、黑、白）= 陆地。
- 世界坐标 ↔ 图像素的线性关系不是猜的：预览图上 6 个**纯蓝出生点圆点**的中心，配上
  `map.xml` 里 `Player_1..6_Start` 的世界坐标做最小二乘拟合：

  ```
  px = -0.90 + 0.09991 * x        py = 604.57 - 0.10000 * y      残差 < 1 像素
  ```
  （1 像素 = 10 世界单位，所以拟合结果就是"图 = 世界的 1/10 缩略图"）
- 降采样成 **153×153 格（每格 40 世界单位）**，按行存"陆地区间"，不在区间里就是海；
  出图范围（地图四角外海）也按海处理。
- 生成脚本：**`tools/build-watermask.js`**（在 `ALittlePlot` 下 `node tools/build-watermask.js`），
  产物 `scripts/lua/chouka/09a_watermask.lua`（6.9 KB，586 个区间），随后照常
  `node tools/sync-scriptsdata.js`。换地图或改了地形，重跑这两个命令即可，判定代码不用动。

## 6.3 验证（离线就能验）

|---|---|---|
| 6 个 `Player_N_Start` | 陆 | ✔ 6/6 |
| 中央 `center` + 两口中央油井 | 陆 | ✔ 3/3 |
| 上一局日志里的抽卡点 (3240,4786) / (3296,5149) | 陆 | ✔ 2/2 |
| 四角 + 四个正方向外海 | 海 | ✔ 8/8 |
| 两岛之间的空海 (2200,3027) / (3900,3027) | 海 | ✔ 2/2 |
| 越界坐标 (-500,-500)、(99999,99999) | 海 | ✔ 2/2 |

> 唯一的"边界争议点"：上一局日志里的 (3591,5150)，掩码说海、地形高度说 100 ——
> 它离最近的陆地像素只有 **1 像素（10 世界单位）**，正卡在岸边线上，属于边界点，不影响判定。

## 6.4 运行时怎么用

```lua

    → ChoukaMaskIsWater(x, y)    -- 查表（09a_watermask.lua）

```

```
[抽卡hex] 抽卡生成 玩家=Player_1 水陆=1 类型=AlliedDestroyer 位置=(3240,4786,0)
```

## 7.4 注释也占节点体积 → 大段说明搬进 docs/10

**结论：会。** `ScriptsData.json` 每个节点的 payload 就是 `#!ra3luabridge\r\n` + lua **原文**，

|---|---|---|

| 最大节点 `抽卡初始化` | 53608 B（余 11928） | **46794 B（余 18742）** |

### ⚠ 这里踩了一个坑（留着当反面教材）

第一版 `extract-comments.js` 按"块升序"依次 `splice`，却没有修正后面块的行号偏移 ——
**2 个块以上的文件，从第 2 个块开始切错位置，删掉的是真实代码**（5 个文件被毁：
`05_dog` / `10_puredraw_data` / `12_puredraw_replace` / `16_buttons` / `17_ai`）。

现在两重保险，别再删掉：

1. 块**从后往前**替换（后面替换不影响前面的行号）；
2. 落盘前比对**代码指纹**（去掉所有纯注释行后的 sha1），不一致就整体中止、一个文件都不写。

另外留了个应急工具：`node .dsh-tools/scratch/recover_all_lua.js` ——
从最后一次同步的 `ScriptsData.json` 里按"横幅起点 + 文件边界 + 代码指纹"把 lua 恢复成同步时原文。

# 八、进游戏怎么验（按顺序）

1. 房主配置页只有 4 个按钮：1=箱子包括全部阵营（默认带 `√`）、2=抽卡只有自己阵营、3=确认、4=重看公告。
2. 确认后公屏出现：`房主完成配置，游戏开始！抽卡范围：…`
3. 立刻出现：`中央油井定位：1号=有 2号=有 1号坐标=(…)`、`中央钱箱：第0回合刷了N个/6个点位`。
4. 顶部有两个抽卡技能；十连一次出 **10 个**单位（现在按落点分组，仍是 10 组 → 10 个）。
5. 派兵站中央油井 ≈15 秒 → 公屏 `中央油井1 被 Player_N 占领！`，
   期间每 5 秒能看到 `中央油井1 领先=… 进度=… 计数=P1-P2-…` 的进度变化。
6. 用一个没单位的号等 5 秒 → 出生点方向出现**工程师**，并收到左下角提示。
7. **海陆**：用船在海上开箱 → 出**海上单位**；陆地开箱 → 出陆地单位。
   日志里每次抽卡都有一行 `抽卡 … 判水=0/1[理由链] 原生类型=…`，判错时把那行发出来就能定位。
8. **一箱多单位**：抽到"运兵车 + 若干步兵"这类组合时，日志应显示 `原生=6个 分1组`、`共补1个`，
