# 03 · 开局判负排查：为什么"没有基地车"就秒负，盲盒高原怎么躲过去的

> 全部结论来自 Ra3MapEditor MCP 实测导出，原始落盘在 `tools/mcp-client/out/`
> （`ref_*` = 盲盒高原，`target_*` = 本仓库的 `[cor]每人一小块地抽卡hex`，`alp_*` = 第一版 `Maps/ALittlePlot`）。

---

## 1 引擎规则：什么算"被击败"

SAGE（RA3）的常规判负是**玩家名下既没有建筑、也没有单位**。也就是说：
**进图第一帧如果你名下对象数是 0，就直接判负**，跟你有没有基地车无关 —— 基地车只是"给你对象的载体"。

所以一张"开局没基地车"的图想活着进游戏，唯一的要求是：**第 0 帧你名下得有东西**。
两条完全不同的路线：

| 路线 | 做法 | 谁在用 |
|---|---|---|
| 造物路线 | 进图瞬间脚本 `CREATE_*` 给你东西 | 本仓库这张图（`每人一小块地` 血统） |
| 预置路线 | 地图上**预先摆好**一个属于你的建筑 | 盲盒高原 |

## 2 本仓库这张图现在是怎么保命的

### 2.1 兜底：6 个藏在边界外的电厂

出生点航点：`Player_1_Start (4927,4110)`、`P2 (4932,1947)`、`P3 (3047,863)`、`P4 (1151,1946)`、
`P5 (1152,4111)`、`P6 (3044,5193)`。

另有 6 个 `AlliedPowerPlant`，**不在可玩区里，而是贴在 border 外侧的一排**：

| 归属 | 世界坐标 | 格 |
|---|---|---|
| Player_1/teamPlayer_1 | (7, −339) | (40, 6) |
| Player_2/teamPlayer_2 | (120, −339) | (52, 6) |
| Player_3/teamPlayer_3 | (230, −343) | (63, 6) |
| Player_4/teamPlayer_4 | (351, −342) | (75, 6) |
| Player_5/teamPlayer_5 | (458, −345) | (85, 6) |
| Player_6/teamPlayer_6 | (587, −348) | (98, 6) |

血 100、`enabled=true`，每人恰好一个 —— 这就是"进图那一瞬间别判负"的记号。

### 2.2 但这块记号正好被自己的清理脚本盖住

触发区实测：

```
Total       x −209 … 6366 , y −290 … 6267      ← 全图
DieAreaBUG  x −111 …  708 , y −399 … −289      ← 正好是上面那排电厂所在的横条
规范方框    (3041,3155)(3168,3031)(3043,2905)(2912,3031)   ← 中心岛
```

脚本组 `修复基地车脚本人机BUG`（全局，本意是"防止 AI 的基地车跑飞出图"）：

| 脚本 | 条件 | 动作 |
|---|---|---|
| `删除电厂` | 无条件 | 每帧把 1 ms 计时器 `1s` 重设一次 |
| `计时1秒` | `{TIMER_EXPIRED(1s) AND 真实 真}` | `UNIT_KILL_ALL_IN_AREA <All Players> DieAreaBUG` |

→ DieAreaBUG 恰好把那 6 个电厂整排包住，且动作对 `<All Players>` 生效。
**开局第一帧之后这排电厂就会被自己扫掉**（如果没被扫掉，这张图反而永远不可能判负）。
所以真正决定生死的是下一节。

### 2.3 正片：脚本把"引擎给的建造场"换成"基地车"

`AI直接给基地__N`（每组玩家一条，`Conmment="防止AI乱跑"`）
条件 `{PLAYER_IS_HUMAN_OR_AI_PERSONALITY <This Player> Human AND 真实 真}`
→ `ENABLE_SCRIPT Player_N/游戏开始：出场动画__N`（该组默认 `IsActive=false`）。

组内 4 条脚本按阵营发车，写法完全对称（下面以 Player_1 为例）：

| 脚本 | 条件 | 动作（顺序） |
|---|---|---|
| `龙船闪亮登场`（神州） | `{玩家拥有 ≥1 个 celestialconstructionyard AND 真实 真}` | SET_REF 最近的建造场→`P1CY` → 在 `Player_1_Start_High` 生成 `celestialmcv` → `NAMED_DELETE P1CY` → 关掉整组 |
| `MCV传送登场`（盟军） | `{… alliedconstructionyard …}` | 同上，`Player_1_Start` 生成 `alliedsuperweaponeffect` + `alliedmcv` |
| `MCV传送登场__1`（帝国） | `{… japanconstructionyard …}` | 同上，`japanmcv` |
| `MCV传送登场__2`（苏联） | `{… sovietconstructionyard …}` | 同上，`sovietmcv` |

**这张图的开局是「引擎先给建造场 → 脚本认出阵营 → 删掉建造场 → 换成对应阵营的基地车」**
（所以 `map.str` 里才写"展开 MCV 以获取视野"）。删建造场那一步是刻意的：基地车是"传送登场"的表演。

### 2.4 于是"没有基地车 = 秒负"的链条

```
玩家名下没有建造场
  → 4 条发车脚本的条件全 false（它们靠"你已有一个建造场"来判阵营）
  → 一辆基地车都不会生成
  → DieAreaBUG 那条脚本又把边界外那排保命电厂扫掉
  → 玩家名下 0 个对象 → 立刻判负
```

反过来，只要**任何一步**保证了"玩家名下从一开始就有一个对象"，这条链就断不了。
盲盒高原走的就是这一条。

> 顺带确认两件事：
> 1. `Maps/ALittlePlot/map.ini` 与 `Maps/[cor]每人一小块地抽卡hex/map.ini` **字节完全相同**（600 B，SHA256 前 16 位 `4D75A14D91CFBFE2`），都还是模板原件 —— 秒负与 map.ini 无关。
> 2. 脚本条件的分组语义是**「同一个 `<OrCondition>` 里是真 AND，多个 `<OrCondition>` 之间是真 OR」**。
>    所以 `{玩家造过 sovietcrane, 真实 真}` 是"造过起重机才成立"，不是"永远成立"；
>    而 `Money` 里那 5 个 `<OrCondition>` 才是"四种建造场或四种 MCV，任一种都算"。
>    （`ra3map_script_detail` 的 `conditions:[{or:[…]}]` 结构可以逐条核对。）

## 3 盲盒高原的做法（实测）

### 3.1 它根本不发车：出生点预置了一台起重机

6 个 `SovietCrane`（苏联起重机），每人在出生点旁边一台，**归属玩家**：

| 归属 | 世界坐标 | 对应出生点 |
|---|---|---|
| Player_6/teamPlayer_6 | (1749, 4541) | Player_6_Start (1872, 4502) |
| Player_5/teamPlayer_5 | (1834, 2488) | Player_5_Start (1964, 2522) |
| Player_4/teamPlayer_4 | (3614, 1500) | Player_4_Start (3607, 1684) |
| Player_3/teamPlayer_3 | (5450, 2491) | Player_3_Start (5329, 2557) |
| Player_2/teamPlayer_2 | (5403, 4469) | Player_2_Start (5282, 4377) |
| Player_1/teamPlayer_1 | (3660, 5519) | Player_1_Start (3653, 5378) |

关键属性：`objectInitialHealth=1000`、`objectEnabled=true`、`objectBasePriority=40`、`objectBasePhase=1`、
`originalOwner=Player_x/teamPlayer_x`。**从第 0 帧起，每个玩家名下就有一栋自己的建筑** ——
判负条件永远不成立，也完全不需要基地车（玩家用起重机起手造建造场）。

### 3.2 配套的三条脚本（全是原生触发器，没有一行 Lua）

| 脚本 | 条件 | 干什么 |
|---|---|---|
| `初始化`（全局，开局一次） | 无条件 | 全场 `PLAYER_SET_MONEY 30000`、`MAP_REVEAL_ALL_PERM` 全图常亮、`DISPLAY_COUNTDOWN_TIMER time`、启用 `计时器`、给 4 个盲盒点 `OBJECT_CREATE_RADAR_EVENT` |
| `定时器`/`计时器`（每 120 单位） | 无条件 | 重置 `time` 倒计时 + 重新打雷达 |
| `固定收入__N`（每 1 秒） | `{真实 真 AND 玩家造过 sovietcrane}` | `PLAYER_GIVE_MONEY 100` → **起重机 = 经济来源** |
| `起重机科技__N`（每帧） | `{玩家造过 SovietConstructionYard AND 真实 真}` | 真：`ALLOW_DISALLOW_ONE_BUILDING 1` 放行兵营/电厂；假：置 0 禁止 |
| `盲盒生成`（每 120 单位） | 无条件 | 4 个中立 `moneycrate`（航点 a1~a4，队伍 `PlyrCivilian`）+ 12 个私有 `unitcratenew`（h1~h12，每人 2 个）+ 雷达提示 |

### 3.3 结论对比

| 维度 | 盲盒高原 | 本仓库这张图 |
|---|---|---|
| 开局保命靠什么 | **地图上预置的玩家建筑**（起重机 ×6，永久存在） | 脚本发的基地车（依赖"你已有建造场"这个前提） |
| 有没有基地车 | **完全没有**，也不需要 | 有，但只在脚本条件成立时才发 |
| 建造入口 | 起重机（能造建造场） | 基地车展开 |
| 经济 | 脚本固定 +$100/s（有起重机时）+ 箱子 | 有建造场/MCV 时 +$8/s + 中心油井 |
| 失败姿势 | 不会出现"开局零对象" | 条件不成立 + 电厂被 DieAreaBUG 扫掉 = 秒负 |

## 4 要改成"没有基地车"的图，建议怎么改

按风险从低到高：

### 方案 A（照抄盲盒高原：预置保命建筑）
在 6 个出生点旁边各摆一个**属于该玩家**的建筑。四阵营都能用的话别用 `SovietCrane`（苏联专属），
建议用各阵营自己的起重机/或任意"无生产功能但血厚"的建筑，**关键是 `originalOwner=Player_x/teamPlayer_x`**。
- 优点：不依赖任何脚本、不会因为脚本报错而丢；`map.ini` 不用动。
- 缺点：4 阵营任选时建筑类型不通用，视觉上多一栋房子；如果玩家不需要建造，就是纯粹占位。

### 方案 B（脚本按阵营发建造场，替代发车）
在**根脚本列表**加一条（或四组）无条件、`EvaluationInterval=0` 的脚本：

```
条件：PLAYER_HAS_PLAYER_TECH  玩家=<This Player>  科技=PlayerTech_Allied / _Soviet / _Japan / _Celestial
动作：CREATE_NAMED_ON_TEAM_AT_WAYPOINT_WITH_ORIENTATION
        对象名 = AlliedConstructionYard / SovietConstructionYard / JapanConstructionYard / CelestialConstructionYard
        队伍   = Player_N/teamPlayer_N
        航点   = Player_N_Start
        角度   = 0
```

要点：
1. **判阵营用 `PLAYER_HAS_PLAYER_TECH`，不要用 `PLAYER_HAS_OBJECT_COMPARISON(xxxconstructionyard)`**
   —— 后者正是现在这张图"鸡生蛋"的地方（要先有建造场才发车）。
2. 这条必须排在其它"删东西"的脚本之前生效（根列表最先，或干脆放在 `初始化` 里）。
3. 想保留"基地车登场"的观感，把对象名换成 `<faction>MCV` 即可；但**别删引擎给的那栋**，除非你已经先发了新的。

### 方案 C（清理脚本收窄）
`修复基地车脚本人机BUG/计时1秒` 的 `UNIT_KILL_ALL_IN_AREA` 现在是 `<All Players>` + `DieAreaBUG`，
而 DieAreaBUG 正好盖住那 6 个保命电厂。要么把电厂挪出该区，要么把这条脚本的玩家限定成
`PlyrCivilian`/`PlyrCreeps`（AI 阵营），别对 `<All Players>` 生效。
