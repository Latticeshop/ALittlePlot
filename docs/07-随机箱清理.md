## 1 DSA 是怎么做的（照抄来源）

《DSA 自走棋》`lua/GAME/PureDraw/06_init_mcv.lua` 第 43–79 行，**两段延迟删除**：

```lua
-- ① 第 1 tick：只删"刷箱子的东西"
SchedulerModule.delay_call(function()
    local crateFilter = CreateObjectFilter({ IncludeThing = { "GenericCrateSpawner" } })
    local units, count = ObjectFindObjects(nil, nil, crateFilter)
    if count <= 0 then
        return
    end
    for j = 1, count, 1 do
        ExecuteAction("NAMED_DELETE", units[j])
    end
    -- 此外假如检测到随机宝箱，就默认启用旧抽卡模式。
    if g_DrawMode == nil or g_DrawMode == 0 then
        g_DrawMode = 1
        g_LuckyCrateMode = 1
    end
    if not g_HextechCountManuallySet then
        g_HextechCount = 3
        ...
    end
end, 1, {})

-- ② 第 45 tick：连"已经刷出来的实体箱子"一起删
SchedulerModule.delay_call(function()
    local crateFilter = CreateObjectFilter({
        IncludeThing = { "GenericCrateSpawner", "UnitCrateNew", "ShroudCrate", "MoneyCrateMP" }
    })
    local units, count = ObjectFindObjects(nil, nil, crateFilter)
    for j = 1, count, 1 do
        ExecuteAction("NAMED_DELETE", units[j])
    end
end, 45, {})
```

这段代码被编进 DSA 的地图节点 **`GAME/UtilsLuckyCrate`**（`EvaluationInterval=0` 每帧、`DeactivateUponSuccess=true`、payload ≈61 KB）。
作者原注释（源码注释被移到 `analysis/地图注释说明文档.md:2051`，附录 A.48.2）：

```
-- 箱子模式：只允许抽卡，不允许在地图上刷随机箱子（万一被 AI 捡了太麻烦）
-- 这个检测也是「局外「开启随机箱子」→ 默认开启抽卡 / 默认开启海克斯（三个）」的唯一读取入口
```

### 为什么要两遍

| 时机 | 干什么 | 为什么 |
|---|---|---|
| 第 1 tick | 删 `GenericCrateSpawner`（引擎的**刷箱器**） | 刷箱器没了 → 引擎之后**不再往图上刷**箱子 |
| 第 45 tick | 再扫一遍，把 `UnitCrateNew` / `ShroudCrate` / `MoneyCrateMP` 等**已经落地的实体箱子**删掉 | 第 1 tick 只能拦住"之后"的刷新；开局那一批实体箱子已经生成了，必须靠第二遍清 |

顺便：第 1 tick 那次"有没有找到 spawner"被 DSA 当成**大厅有没有勾「开启随机箱子」的唯一探针**（找到 → 默认开抽卡 + 默认海克斯 3 次）。本图也把这个探针留下了（`CHOUKA_LOBBY_CRATE_ON`），以后要联动别的系统可以直接用。

## 2 本图的实现（`07_crates.lua`）

### 2.1 时序

| 帧 | 动作 |
|---|---|
| **1** | 删 `GenericCrateSpawner`（全部）→ 之后引擎不再刷箱；删到就置 `CHOUKA_LOBBY_CRATE_ON = 1` |
| **45** | 先再清一遍生成器，再扫 5 种自然箱 → **离预设点位 80 以内的放过**，其余删掉；删到就在公屏报一句 |
| 之后 | 前 2 分钟（≤7200 帧）每 600 帧（≈10 秒）兜底补扫一次，防止某些箱子比开局动画还晚落地 |

节点 `EvaluationInterval = 0`（每帧）、`DeactivateUponSuccess = false` —— **不能设成一次性**，
否则第 1 帧成功后节点自我停用，第 45 帧那遍就永远跑不到。

### 2.2 删哪些、留哪些

删（`CHOUKA_CRATE_NATURAL` + `CHOUKA_CRATE_SPAWNER`）：

| 类型 | 说明 |
|---|---|
| `GenericCrateSpawner` | 引擎的随机箱**生成器** → 永远删，**不看保留点位**（留着它就一直刷） |
| `UnitCrateNew` | 原版单位箱（随机箱主要实体） |
| `UnitCrate` | 原版单位箱（旧模板名） |
| `ShroudCrate` | 迷雾箱 |
| `MoneyCrateMP` | 原版金钱箱 |
| `MoneyCrate` | 原版金钱箱（旧模板名） |

前 4 个（生成器 + `UnitCrateNew`/`ShroudCrate`/`MoneyCrateMP`）是 DSA 的原表，后两个是同一箱族里的旧模板名。

**绝对不删**的两种（加进去会直接把玩家的箱子干掉）：

| 类型 | 为什么不能删 |
|---|---|
| `LuckyUnitCrateSeed` | 抽卡技能（`SpecialPower_LuckyUnitCrate`）扔出来的可拾取箱子，本图抽卡的入口对象 |
| `moneycrate` | 本图自己的金钱箱（`02_private_box.lua` / `06_center.lua` 刷的） |

### 2.3 「保留点位」判断

模板名大小写不敏感时 `moneycrate` 和 `MoneyCrate` 可能是同一个东西 —— 为了**绝不误删自家箱子**，
删除前多一道几何判断：箱子离下面任一航点 ≤ `CHOUKA_CRATE_KEEP_RANGE`（80 世界单位）就放过。

```
box1~box6（老写法兜底）   box11 box12  box21 box22  box31 box32
box41 box42  box51 box52  box61 box62   center1~center6
```

自家箱子永远是 `CREATE_UNNAMED_ON_TEAM_AT_WAYPOINT` 直接刷在航点上（偏差 ≈0），
而引擎随机箱落在刷箱器附近，两者不会撞。点位两点之间相距约 70，所以半径 80 既够容住自家箱、
又不至于把旁边的引擎箱一起放过。

## 3 进游戏怎么验

1. **大厅勾上「开启随机箱子」**（有这选项的话），开一局。
2. 开局公告期间 / 开局后，**全图都看不到随机箱**（尤其刷箱器原来所在的角落）。
3. 公屏可能出现一句「已清除 N 个引擎随机箱子（本图只在预设点位刷箱）」。
4. **自家箱子必须还在**：
   - 开局后 120 秒 `boxN1` / `boxN2` 各刷一个金钱箱（每人两个）；
   - 每回合 `center1~center6` 各刷一个金钱箱；
   - 抽卡技能扔出来的箱子能正常捡、正常开。
5. 若发现某个自家箱子被误删：把它的类型从 `CHOUKA_CRATE_NATURAL` 去掉，
   或把它的航点加进 `CHOUKA_CRATE_KEEP_WPS`。

### 不确定项

| 项 | 说明 |
|---|---|
| `GenericCrateSpawner` 是否就是日冕的随机刷箱器 | 按 DSA 作者注释 + 命名推断；如果删了它箱子照刷，说明刷箱走的是别的路径，需要在游戏里再找类型名 |
| 45/600/7200 帧这几个数 | 按"每帧求值"估的（60 帧 ≈ 1 秒）。若发现 `EvaluationInterval = 0` 不是每帧，按实际倍数调整 |
| `MoneyCrate` / `moneycrate` 是否同一模板 | 正因为不确定才加了「保留点位」判断，两种情况下都不会误删自家箱 |

> 它的模型是通用木箱 `NPCrate01`，而原版属性箱是"给捡箱子的单位加一个临时属性 buff"，
> 日冕里真正生效的是那二十来个具体变体（`AttackSuperUpAttributeCrate` / `ArmorUpAttributeCrate` / `SpeedUpAttributeCrate` …），
> 基类 `AttributeCrate`（地编 `CrateAttribute`）看着像空箱就是这个原因。三种处理：
> ① 权重改 0 先不刷；② 换成某个具体变体（效果固定一项属性）；③ 等下面的自定义改造。
>
> 属性箱的下一步（作者规划）：参考 DSA 登神符文的"四维登神"改成自定义效果 ——
> 箱子被碰掉后，**点位附近的单位随机获得某一项属性加成**，并给该玩家播报具体加了什么。
> 现在的 `AttributeCrate` 还是原版箱子，改造时把它从表里换成自定义触发即可。

### 5.1 登神盲盒（`AttributeCrate` 的自定义效果，已实装）

作者 2026-10 定稿：那个"通用木箱 `NPCrate01`、捡起来毫无效果"的箱子就是属性箱 `AttributeCrate`，
现在给它换成了**登神盲盒**（照 `DSA_ggz自走棋/lua/GAME/HextechRune/06_ascension.lua` 的"登神"）：

| 项 | 规则 |
|---|---|
| 触发 | 箱子被碰掉（对象消失）后 1 秒内结算；实现方式是"刷箱时登记箱子 id + 点位 + 归属玩家"，然后每秒扫一次 `ChoukaAscendTick` |
| 影响谁 | **只影响箱子点位周围 96 世界单位内、且是箱子主人自己的**非建筑单位（一般 3~5 个）——不是玩家全部单位。<br>96 = 作者定的基准：家里 `box11`↔`box12` 的间距 **95.5**（(5066,4310)→(5136,4245)，dx70 dy65）；直径 192 ≈ 两个箱子点的跨度 |
| 加成种类 | 血量 40% / 伤害 30% / 攻速 20% / 射程 10%（累计 0.40 / 0.70 / 0.90 / 1.00；与 DSA 同概率）|
| 加成幅度 | **25% ~ 50%**（每只箱子掷一次；同一只箱子罩到的单位拿到同一个数）|
| 怎么加 | `exAttributeModifierCreate({ HEALTH_MULT / DAMAGE_MULT / RATE_OF_FIRE / RANGE+VISION }, 1)` + `ObjectLoadAttributeModifier(单位, mod, 999999999)`<br>第三个参数是**帧**（30 帧 = 1 秒），DSA 写 9999（≈5.5 分钟），这里照巨人城废墟-登神工程的 `permanent_frame_count` = 999999999，整局不消 |
| 射程特例 | 射程必须和 `VISION` 成对写，否则单位站在射程边缘却看不见目标（DSA 注释里的坑）|
| 播报 | **只播给箱主一个人**：`exAddTextToPublicBoardForPlayer(箱主, "登神盲盒：射程 属性 提升 37%", 10)`，不刷屏 |
| 日志 | `登神盲盒：玩家=Player_1 点位=(5066,4310) 射程 +37% → 3 个单位` |

调参都在 `02_private_box.lua` 开头：`CHOUKA_ASCEND_TYPE` / `CHOUKA_ASCEND_RADIUS`（96 = box11↔box12 间距 95.5）/
`CHOUKA_ASCEND_MIN` / `CHOUKA_ASCEND_MAX`（25 / 50）/ `CHOUKA_ASCEND_DURATION`（9999 秒）/ `CHOUKA_ASCEND_LOG`。

### 5.2 登神**累计**（同一只单位吃两次同种加成要往上加，不是各自乘一遍）

引擎里每条 AttributeModifier 是**相乘**的：直接再挂一条 +40%，结果是 1.4×1.4 = 1.96（+96%），
不是累计想要的 1.8（+80%）。想变成"1 + 已有% + 本次%"这一条，只能重算；但卸载
`exAttributeModifierCreate` 造出来的 modifier 不一定好使（DSA 干脆一次重算一条）。

所以这里用「**补差额倍数**」的写法，完全不需要卸载：

| 步 | 做什么 |
|---|---|
| 1 | 单位登记表 `ChoukaAscendUnitStacks[单位id]` 记着这只单位各维**已累计的 %**（`health` / `damage` / `rateOfFire` / `range`）。**每个单位一条记录**，没吃过箱子的单位根本没有记录（等价 0）|
| 2 | 基准倍数 = 1 + 已有% / 100（**只用登记表**，绝不查引擎）|
| 3 | 目标倍数 = 1 + (已有% + 本次%) / 100 |
| 4 | 补的倍数 = 目标倍数 ÷ 基准倍数 → 新挂**一条** modifier；因为 modifier 相乘，已有 × 补 = 目标 ✔ |
| 5 | 单位死了自动从登记表删掉（每秒 `ChoukaAscendPruneStacks`；不清的话单位 id 被新单位复用会串加成）|

**为什么基准不能用 `ObjectGetAttributeModifier` 的实时值**：实时值里混着协议/技能等**外部 buff**。
拿它当分母会把登神的加成稀释掉——例：外部已有 +40%，我们目标 +41%，
用 1.4 当分母只需补 1.007，玩家实际只多得 0.7%，而不是应得的 41%。
所以引擎实时值只写进日志（`引擎核对 %.3f`）用来验证"确实是相乘"，不参与计算。

**同一只箱子罩到不同历史的单位，各算各的**（假设这次掷到攻速 +41%，半径内 3 个"吃过一次 +41%"的 + 2 个全新的）：

| 单位 | 登记表旧值 | 补的倍数 = 1.82/1.41 / 1.41/1.00 | 引擎里最终 | 累计 |
|---|---|---|---|---|
| 吃过一次的那 3 个 | 41% | 1.2908 | 1.41 × 1.2908 | **+82%** |
| 全新的那 2 个 | 0 | 1.4100 | 1.00 × 1.41 | **+41%** |
| 半径外没被罩到的 | — | 不动 | — | 不变 |

这样：① 累计语义和 DSA 的"1 + n×p%"一致；② 引擎查询做兜底校正，外部 buff（协议/技能）已经加过也算得对；
③ 登记表还能在日志里报"这只单位现在累计多少"（日志末尾的 `最高累计 %d%%`）。

`CHOUKA_ASCEND_LOG` 每只箱子一行：
`登神盲盒：玩家=Player_1 点位=(5066,4310) 攻速 +41% → 3 个单位（最高累计 82%）`

⚠ 剩下的一个已知行为：箱子**没被捡**就一直留在点位上（`ChoukaBoxBusy` 会挡住同点位再刷），这是原有行为，与登神无关。

### 加/换箱子时必须同时注意三件事

1. **点位占用过滤器**：`ChoukaCrateFilterTypes()`（`02_private_box.lua`）用的是本表所有 `weight>0` 的类型，
   不在表里的箱子类型不会被"这个点还有没有箱子"看到 → 同一个点会越刷越多。加类型只改表就行，过滤器自动跟随。
2. **别被随机箱清理误删**：`07_crates.lua` 只删"离预设点位 80 世界单位以外"的引擎随机箱，
   我们刷在点位上的箱子（含 `UnitCrateNew` 这种同时在"自然箱"名单里的）都在保留范围内。
3. **日志**：`CHOUKA_BOX_CRATE_LOG = 1` 时每刷一个箱子都会写一行
   `刷箱：box21[家里] 类型=HealCrateMP（治疗箱）`，进游戏看日志就知道刷出来的是什么。
