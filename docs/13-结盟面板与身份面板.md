## 1. 为什么重做身份 UI

原来的三国杀身份面板只有一条路：**顶部按钮的悬浮说明（desc）**。这条路有个死结：

| 通道 | 是否替换 `$p<N>Name` | 证据 |
|---|---|---|
| `exAddTextToPublicBoard*`（公屏） | ✅ 替换 | 教程.lua:410/420 |
| `exScoreBoardSetText*`（计分板） | ✅ 替换 | 本图 `20_hud.lua:93` |
| `exAddTextToMessageArea` | ✅ 替换 | 本图实测 |
| **`exCenterTopBtnShowForPlayer` 的 desc** | ❌ **不替换** | 本图实测：原样显示 `$p6Name` |
| `exAddTextToPublicBoardForPlayer`（逐玩家公屏） | ✅ 替换 | 官渡 `RolesShow` 把 `$p<i>Name` 直接塞进去（`145_code.txt:761`） |
| `exCreateCustomTextForPlayer` 的 Content | ⚠️ **待实测** | 官渡玩家列表页据此显示真名，但源码层面无直接证据；本图已加公屏兜底（见 §5.2） |
| `_LOG` / 日志 | ❌ 不替换 | — |

而**取真实昵称的原生 API 不存在**：LuaLib `PlayerModule.get_player_nickname` 已被官方整段注释并标注"该功能已被删除"（官渡版 `38_code.txt:110`），本图 `exGetPlayerNickNameByScriptName` 同样拿不到可用值 → `00_alert.lua` 里只能做"取到真名就用真名，取不到就退回 `$p<N>Name` 占位符"的双层兜底。

结论：**想要在面板里看到真实玩家名，就必须走自定义文字（custom text）通道**。这正是官渡之战"底部能正确展示玩家名字"的原因，也是这次整套照搬官渡 UI 的根本理由。

## 3. 索引分段（照搬官渡）与坐标（已按实机反馈调整）

### 3.1 索引分段

| 段 | 值 | 用途 |
|---|---|---|
| `CHOUKA_PANEL_BTN_OPEN` | **5** | 顶部第 5 个按钮 = 唯一入口（3=交易市场，4=海克斯）。**不另开第 6 个按钮** |
| `CHOUKA_PANEL_GROUP` | 1100 | 自定义按钮/文字的分组号 |
| `CHOUKA_PANEL_I_CLOSE` | 1101 | 关闭面板 |
| `CHOUKA_PANEL_I_PLAYER` | 1110 | +1..+6 = 第 1..6 个玩家色块（点了直接结盟） |
| `CHOUKA_PANEL_T_TITLE` | 1151 | 标题文字 |
| `CHOUKA_PANEL_T_HINT` | 1152 | 提示文字 |
| `CHOUKA_PANEL_T_PLAYER` | 1160 | +1..+6 = 玩家名字/状态（**真实名字走这里**） |
| ~~1102 / 1130+ / 1180+~~ | — | 操作页拆掉后空着，留着防以后撞号 |

> 官渡把 `1110`/`1130` 这两个**基数本身留空**，只用 `基数+1`，所以判断一律写成
> `index > BASE and index <= BASE + count`。移植体照抄了这个边界，否则点第 1 个玩家会误判。

### 3.2 坐标（`AlignX="left"`，`AlignY="top"`，X 从左量、Y 从屏幕顶往下量，1366×768）

官渡原值（头像 104、列距 82、字号 12、每个头像下三行字）在实机上会被引擎强制换行，
所以这一版**放宽列距行距、字号降一级、每个格子只留两行**：

| 元素 | X | Y | 尺寸 / 字号 |
|---|---|---|---|
| 标题 | 120 | 76 | 字号 20 |
| 提示 | 120 | 106 | 字号 13 |
| 关闭按钮 | 780 | 72 | 76×46（右边缘 856，仍在 1366 内） |
| 玩家头像 | `108 + col*168` | `146 + row*170` | 84×84 |
| 玩家文字（名字 / 状态两行） | 头像 X + 6 | 头像 Y + 90 | 字号 11 |

玩家头像 6 列一行排完（最后一列右边缘 `108+5×168+84 = 1032`，屏宽 1366）。
间距是按"文字要放得下 3~4 个字"倒推的：全角字宽 ≈ 字号，状态词最长 4 字 = 44 px，
而每列可用 168 px，宽裕；文字槽还用 12 个全角空格（132 px）的占位内容撑开盒子。
按钮尺寸一律用 `SizeX`/`SizeY` 显式给，不依赖贴图原尺寸 —— 官渡靠的是打包贴图自带的 104×104，
换图源排版就会飘。
## 4. 贴图

| 用途 | 来源 | 说明 |
|---|---|---|
| 官渡的 7 个动作图标 + 兜底 `Unknown` | **官渡的打包贴图**（3 个节点，83 KB） | 操作页删了暂时没用上，留着给以后（比如海克斯）|
| 关闭按钮 | `images/ui/hextechRemoveButton.png` → WebP → base64 | `ChoukaUiBtnRemove` |
| （备用）返回按钮 | `images/ui/hextechUndoButton.png` → WebP → base64 | `ChoukaUiBtnUndo`，面板现在不用，留给海克斯 |
| 玩家头像 | **代码生成的 8×8 纯色块**（7 色） | `ChoukaUiColor*`，无源文件 |

PNG 导入的完整做法见 **`docs/14-自定义图片导入.md`**（关键点：引擎吃的是 **WebP** 容器，
`compression='DXT5'` 只是显卡上传格式，所以 PNG 必须先过 ffmpeg 转 WebP）。

### 玩家颜色怎么来

头像的底色就是该玩家在局内的颜色 —— 照搬官渡 `BangGetPlayerColorIcon`（官渡也是拿色块当头像，
不是单位图）。`exPlayerGetColor()` 取色后用红色通道映射（照抄 `BangMakeColorName`）：

| 红色通道 | 20 | 50 | 102 | 125 | 225 | 230 | 237 |
|---|---|---|---|---|---|---|---|
| 颜色 | 绿 | 蓝 | 青 | 紫 | 橙 | 红 | 黄 |
| 贴图 | `ChoukaUiColorGreen` | `…Blue` | `…Cyan` | `…Purple` | `…Orange` | `…Red` | `…Yellow` |

结果按座位缓存进 `ChoukaPlayerColorCode`，只查一次。

**色块是「容器 + 色块」而不是一整块纯色**（作者要求）：贴图是 96×96 的
`3px 浅色边框 + 深色内衬 + 居中 66×66 色块`，显示成 84×84 时色块约 58 px，
比整块纯色顺眼，也和官渡的"边框+色块"一致。这三层是 `tools/build-ui-assets.js`
用 ffmpeg 的 `drawbox` 画出来的，没有源图片文件。

### 按钮尺寸

hextech 的关闭是 **76×46 的横条**，所以 `SizeX/SizeY` 必须按 76/46 给（不能用正方形）。
关闭按钮放在 **(780,72)** —— 作者按实机效果定下的位置（610 → 660 → 810 → 770 → 780）。
所有按钮的尺寸都由 `ChoukaPanelCreateButton(..., sx, sy)` 显式传入，不依赖贴图原尺寸。

## 5. 交互（只有一页）

```
点顶部第 5 个按钮（唯一的入口）
   │
   ├─ 面板没开 → 玩家列表
   │     标题：结盟面板：选择玩家 / 身份面板：选择玩家
   │     提示：点玩家色块直接结盟，再点一次解除；顶部第 5 个按钮收起面板
   │     [关闭] + 每个座位：色块头像 + 两行字「真名 / 状态词」，主公多一行「主公」，无悬浮说明
   │
   ├─ 点某个人的色块 → **直接结盟 / 直接解除**，然后原地重画列表（状态词立刻变）
   │     → 点自己：提示"不能选择自己"
   │     → 已阵亡的人：不响应
   │     → 三国杀里违反阵营规则（同阵营才能结盟）会被 `ChoukaPanelCanAlly` 挡下并提示
   │
   └─ 面板已开 → 点同一个按钮（或点 [关闭]）收起
```

> **没有第二页了。** 官渡的"目标操作页"（7 个操作按钮 + 返回键）被作者砍掉：
> 那些快捷语句播报没有实际作用，只留结盟这一个真功能。删掉的东西：
> `ChoukaPanelShowActions` / `ChoukaPanelHandleAction` / `ChoukaPanelActionIcon` /
> `ChoukaPanelRelationText` / `ChoukaPanelSlotOf` / `ChoukaPanelIconBack`，
> 以及索引段 1102 / 1130+ / 1180+ 和 22 个不再使用的文字键。

### 播报只留 4 条

结盟/解除时全图播报（`ChoukaAlertFor`，10 秒，日志 + 消息区 + 公屏）：

| 键 | 文案 |
|---|---|
| `panelBcAllyOne` | `%s 对 %s 发起单向结盟` |
| `panelBcAllyBoth` | `%s 和 %s 已经双向结盟！` |
| `panelBcBreak` | `%s 解除了对 %s 的结盟` |
| `panelBcBreakBoth` | `%s 和 %s 的双向结盟已解除` |

其余广播（进攻 / 被进攻 / 警告主公 / 围攻 / 护主 / 停战）连同文字键一起删了。

### 名字只有一条通道（公屏名单已删）

面板里的玩家名走**自定义文字**（`ChoukaPanelPlayerLabel` → 1161~1166 文字槽），
这一条实机确认能显示真名（`$p<N>Name` 会被替换）。

> 早期版本还有第二条腿：打开面板时用 `exAddTextToPublicBoardForPlayer` 往公屏推一份
> `真名 ｜ 关系 ｜ 身份` 名单，作为"万一文字槽不替换"的兜底。**作者要求删掉了**
> —— 面板里信息已经完整，再刷一遍公屏是噪音。所以现在`ChoukaPanelBoardRoster` /
> `ChoukaPanelBoardLine` / `panelBoardSep` 都不存在了。
> 副作用：如果哪天实机发现文字槽显示的是 `$p6Name`，名字就没有兜底通道了，
> 那时要把 `ChoukaPanelPanelName` 改成显示 `"\" .. seat .. \"号位"`。
### 身份可见性（别把别人的身份漏出去）

`ChoukaPanelRoleText(viewerSeat, seat)` 的规则与悬浮框（`docs/11` §6③）完全一致：

| 谁的身份 | 谁能看见 |
|---|---|
| 自己的 | 自己 |
| 主公 | **所有人**（三国杀里主公本来就是明牌） |
| 已阵亡者 | 所有人（阵亡即公开，见 `33_bang_win.lua` 的阵亡通报） |
| 其余（忠臣/反贼/内奸，活着） | **只有他自己**，别人那格不显示身份行 |

这条规则同时作用于文字槽和公屏名单 —— 否则面板一开就等于全场身份公开，三国杀就没得玩了。

## 6. 结盟模型

```
ChoukaAllyFrom["Player_3"]["Player_5"] = 1     -- 3 号单向对 5 号结盟
```

- **结盟**：写单向记录 + `ExecuteAction("PLAYER_RELATES_PLAYER", 3号, 5号, "Neutral")`。
  官渡用的是 `Neutral` 而不是 `Friend`（照抄，别改成 Friend）。
- **双向结盟**：双方各点一次对方的"结盟"。第二次点击时检测到反向已有记录 → 播报"已经双向结盟"。
- **解除**：删单向记录 + 设 `Enemy`。若本来双向，两边一起解并播报"双向结盟已解除"（官渡只解一边却播报双向，这里做了修正）。
- **三国杀限制**：只能同阵营结盟；主公与忠臣视为同一阵营（`ChoukaBangIsLordSide`）。违规点结盟 → 私聊提示"只能和同阵营的玩家结盟"，不改关系。

`PLAYER_RELATES_PLAYER` 必须包在 `SetWorldBuilderThisPlayer(1)` 里才生效——官渡的 `setAlliance` 就是这么写的，移植体照抄。

## 7. 两种模式的区别

| | 三国杀模式 | 常规混战 |
|---|---|---|
| 顶部按钮 | **第 5 个（岚影刺图标）**：悬浮框看身份，点一下开面板 | **同样是第 5 个**，换成原版**盟军间谍**图标，去掉身份相关的一切 |
| 玩家列表 | 参战座位（`ChoukaBangSeats`） | 有起重机的座位（`crane1~6`） |
| 头像 | 玩家颜色色块（边框+色块） | 同左 |
| 每个玩家显示 | 真名 + **主公行** + 状态词 | 真名 + 状态词 |
| 悬浮说明 | 无（这一页全部去掉） | 无 |
| 点色块 | 直接结盟（同阵营限制） | 直接结盟（不限制） |
| 结盟限制 | 只能同阵营 | 不限制 |
| 结算后 | 自动收掉面板 | 面板留着 |

不判 `CHOUKA_MODE` 的函数一个都没有——面板节点本身对两种模式都开放，只把"身份""主公相关操作""同阵营限制"这三处包在 `if CHOUKA_MODE == 1` 里。

## 8. 踩过的坑（都是官渡源码里的坑，移植时避开）

1. **`exCustomBtnRemove(index)` 是全局删除**：官渡在 `exCustomBtnRemoveForPlayer` 不存在时会退化到它，会连带删掉别的玩家同 index 的按钮。移植体**故意不做这个兜底**。
2. **`left_mouse_down` 语义反直觉**：官渡里 `left_mouse_down == 0` 表示"左键**没有**按下"（即右键），并且直接吞掉（`handled=1`）不再转发。本图 `onCustomBtnClickEvent` 只有两个参数，拿不到这个值，所以**面板内所有点击都按左键处理**——想加右键菜单得先验证第三个参数的实参类型。
3. **`BangUiToggle` 是二态开关**：面板开着时点顶部按钮就是直接关掉，不是"返回上一页"。本图只有一页，所以没有返回键的需求 —— 这也是砍掉操作页之后天然对齐官渡行为的一点。
4. **橙色/紫色色块在官渡里其实是坏图**：`BangGetColorIconByName` 引用的 `Orange`、`Color_purple` 全局在资产里根本不存在，一律显示成 `Unknown`。本图不用官渡那套贴图，7 种颜色全部自己代码生成（`ChoukaUiColor*`），所以没有这个坑。
